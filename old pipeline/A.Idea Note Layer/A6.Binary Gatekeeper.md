# ЭТАП 0 — Проверка входов и версионирования

## Правило наличия файлов

Если физически отсутствует любой из обязательных файлов → немедленный BLOCK:

```yaml
status: BLOCK
reason: missing_input_file
missing_files:
```

## Правило версионирования

Версионирование — это метаданные для трассируемости, не gate-условие.

Если `artifact_meta.version` отсутствует в артефакте:

* файл считается актуальной версией
* version автоматически присваивается как `"unversioned"`
* фиксируется предупреждение:

```yaml
versioning_warnings:
  - artifact:
    warning: "artifact_meta.version отсутствует — присвоено 'unversioned'"
```

Отсутствие version **не является основанием для BLOCK**.

## Правило artifact_meta

Если `artifact_meta` полностью отсутствует — агент восстанавливает минимальную структуру:

```yaml
artifact_meta:
  artifact_type: unknown   # восстановлено из имени файла
  version: unversioned
  created_at: unknown
```

и фиксирует warning. BLOCK не выставляется.

# ЭТАП 2 — Cross-Review Conflict Detection

A6 обязан выполнить следующие проверки:

```yaml
cross_review_checks:
  - check_id: icp_vs_segment
    compare:
      field_a: marketing_review.icp_hypothesis.primary_icp_profile
      field_b: vision.target_segment_definition
    conflict_if: явное противоречие между ICP и исходным сегментом
    result: conflict/no_conflict
    explanation:

  - check_id: positioning_vs_value_mechanism
    compare:
      field_a: marketing_review.positioning_draft.differentiation_axis
      field_b: idea_note.value_mechanism.primary
    conflict_if: differentiation_axis противоречит value_mechanism
    result: conflict/no_conflict
    explanation:

  - check_id: functional_change_vs_automation
    compare:
      field_a: marketing_review.functional_impact_suggestions
      field_b: architecture_review.automation_stability_analysis.automation_stability_score
    conflict_if: предложенные изменения критически снижают automation_stability
    result: conflict/no_conflict
    explanation:

  - check_id: guardrails_vs_mvp
    compare:
      field_a: ethics_review.guardrails
      field_b: idea_note.mvp_concept.mvp_core
    conflict_if: guardrail требует исключить элемент из mvp_core
    result: conflict/no_conflict
    explanation:
```

Если любой `result: conflict` → BLOCK.

# ЭТАП 3 — BLOCK Conditions

BLOCK если выполняется любое:

1. Физически отсутствует обязательный входной файл
2. Любой агент дал `recommendation: block`
3. `hitl_intensity_forecast = high` **И** `primary_hitl_triggers` не задокументированы или пусты
4. `automation_stability_score < 6`
5. `regulatory_exposure_level = high` и guardrails неадекватны
6. ≥1 critical gap в architecture_review
7. Любой `cross_review_check.result = conflict`
8. `unresolved_fields` содержит поле с `impact: blocking`

**Отсутствие `artifact_meta.version` не является BLOCK-условием.**

---

## Особое правило: HITL = high с задокументированными триггерами

Если `hitl_intensity_forecast = high` **И** `primary_hitl_triggers` задокументированы:

* статус **не BLOCK**
* фиксируется `hitl_elevation_notice` в final output
* добавляется обязательный пункт в `owner_confirmation_required`:
  "Подтвердить готовность к высокому HITL и принять задокументированные триггеры как известные точки вмешательства"
* все `primary_hitl_triggers` переносятся в snapshot для следующего слоя

```yaml
hitl_elevation_notice:
  hitl_intensity_forecast: high
  triggers_documented: true
  owner_confirmation_required: true
  note: >
    Высокий HITL является характеристикой процесса разработки,
    а не блокером. Все точки вмешательства задокументированы
    и переданы в следующий слой.
```

# ЭТАП 6 — Формирование Snapshot (обязательный артефакт при PROCEED)

Snapshot формируется **всегда при PROCEED** и является обязательным входом для B1.
Без сформированного snapshot переход в B1 невозможен.

Snapshot — это не дайджест и не краткое резюме. Это **полная передача состояния слоя**.

Принцип формирования:
* всё что проработано и подтверждено → переносится как **инвариант** (frozen)
* всё что открыто, оспорено или требует решения → переносится как **явный список для закрытия в Layer B**
* ничего не теряется молча

Snapshot — отдельный файл `IdeaNoteLayer.snapshot.yaml`, передаётся в B1 вместе с `final_gate_decision.yaml`.

# ЭТАП 7 — Final Output при PROCEED

При PROCEED A6 обязан выпустить **два артефакта**:

1. `final_gate_decision.yaml` — решение гейта
2. `IdeaNoteLayer.snapshot.yaml` — снэпшот слоя (сформирован в ЭТАП 6)

Оба артефакта являются обязательными входами для B1.
Передача только `final_gate_decision.yaml` без snapshot недопустима.

```yaml
final_gate_decision:
  layer: IdeaNote
  status: PROCEED
  versioning_warnings:    # если были в ЭТАП 0
  rationale:
    - bullet:
  output_artifacts:
    - artifact: final_gate_decision.yaml
      required_for: B1
    - artifact: IdeaNoteLayer.snapshot.yaml
      required_for: B1
      status: mandatory   # B1 не запускается без этого файла
  next_step:
    agent: B1
    artifact_to_generate: concept.yaml
    interview_mode: owner_confirmation
    required_inputs_for_next_agent:
      - IdeaNoteLayer.snapshot.yaml   # обязательно
      - final_gate_decision.yaml      # обязательно
    required_constraint_for_next_agent: >
      Все элементы со статусом RECOMMENDATION_ONLY
      не могут быть включены в concept.yaml
      без явного подтверждения владельца.

owner_confirmation_required:
  - "Подтвердить mvp_core как финальный scope."
  - "Подтвердить каждый RECOMMENDATION_ONLY пункт."
  - "Ответить на все safety_questions_for_owner из ethics_review."
  - "Подтвердить assumption_map со статусом challenged."
  - "Подтвердить domain_entities — нет лишних, нет отсутствующих."

layer_exit_criteria:
  gate_status: PROCEED
  ready_for_concept: true
  snapshot_generated: true   # явное подтверждение что snapshot сформирован
```
