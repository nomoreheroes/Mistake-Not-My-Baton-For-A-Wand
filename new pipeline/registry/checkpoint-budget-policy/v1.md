# Checkpoint budget policy v1

**Source YAML:** `new pipeline/registry/checkpoint-budget-policy/v1.yaml`  
**Policy ID:** `checkpoint-budget-policy`  
**Status:** proposed for owner approval

## Thresholds

| Parameter | Value |
|---|---:|
| Maximum checkpoint | 100 MiB |
| Maximum projected pack growth per phase | 1 GiB |
| Maximum publications per run | 12 |
| Publication p95 | 10 seconds |
| Clean-clone restore | 120 seconds |
| Warning ratio | 0.5 |
| Hard-stop ratio | 1.0 |
| Unpublished window | 10 replay points / 5 minutes / 32 MiB |

The pre-K0-b no-delta factor is 1.0. It is not an expected Git-growth estimate. Expected delta and pack growth remain unknown until K0-b.

Publication-window enforcement applies from K0-b, when the checkpoint publisher exists. Pre-publisher phases such as K0-a may calculate counterfactual window pressure for planning, but are explicitly exempt and have an effective publication count of zero.

Phase publications are derived from per-run triggers: run completion, human wait/exit, irreversible boundaries, migration/gates and replay/time/DB-growth windows.

Every size threshold is evaluated per project checkpoint chain. Fixture DB bytes never become the opening balance of the Swarm DB. Forecast `threshold_status` is a two-axis structure: checkpoint and phase pack are classified independently as below warning, above warning or above hard; pack may additionally be `publisher_unavailable`.

Window-driven publication count uses the maximum of replay-point, elapsed-runtime and new-DB-byte minima. Replay points include model, human answer/approval, external tool and irreversible side-effect intent/result boundaries. Before measurement, publications forced by another trigger receive no overlap credit.

## Crossing a threshold

Warning requires an owner route before continuation. Hard stop blocks the next product/external action. The publisher may create one terminal `over_limit` checkpoint for the current unpublished range; only recovery, migration evidence and owner disposition remain permitted.

Allowed routes are:

- narrow scope or checkpoint batching;
- raise a threshold with storage/clone evidence;
- migrate checkpoint storage, which reopens V2-D22;
- pause.

No LFS, CAS or external backend is enabled automatically. The last cheap migration gate is V1-00 before V1-01. Migration after V1-01 requires an architecture change.

## Evidence

K0-b must measure SQLite page churn, media-BLOB distribution/compressibility, full rewrites such as `VACUUM`, snapshot/commit p95, actual Git-pack delta and clean-clone restore. G/Q later replace their D0 binary assumptions with layer-plan budgets and real evidence.
