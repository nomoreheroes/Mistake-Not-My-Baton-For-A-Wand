# Approval envelope schema v1

**Source schema:** `new pipeline/registry/approval-envelope/v1.schema.yaml`

The schema binds this Markdown projection through `x-pipeline-projection.path + sha256`; the validator rejects a changed projection until that binding is republished.

The envelope is the machine-readable carrier for a human authorization. It records:

- actor identity/role and available authentication reference;
- timestamp and authority;
- approval outcome;
- exact SHA-256 of every canonical record and human-readable projection;
- per-decision dispositions and explicit overrides;
- approved scope;
- provenance and its limitations;
- a canonical payload hash.

For `d0_decision_baseline`, the generic JSON Schema count is supplemented by a deterministic Pipeline validator: the decision-ID set must equal V2-D01…V2-D39 exactly, duplicate IDs are rejected, and the `records` array must contain exactly one each of `dispositions`, `forecast`, `gate_contract` and `checkpoint_policy`. Other approval types may omit the disposition array when it is not meaningful.

The internal integrity hash uses the path, version and exact SHA-256 of `canonical-yaml-v1` from `registry/hash-profiles/canonical-yaml-v1.yaml`, excluding only `integrity.canonical_payload_sha256`. The complete-file hash is recorded externally by the enclosing Git/SQLite approval record. This avoids a self-referential hash while keeping the approval addressable.

`conversational_only` is permitted before the runtime approval mechanism exists, but must declare that actor authentication and a stable external message identifier may be unavailable.
